# BC125AT_PROTOCOL.md §7.6 does not document — it lists only 0/1/2. The earlier
# two captures never asked about it. Question: is `CC Only` a fourth CLC mode

# VERDICT: `CC Only` IS a fourth CLC mode digit — mode 3. The reference is
# incomplete, not wrong: 0/1/2 match §7.6 exactly (confirming the earlier two
# captures a third time), and 3 is simply absent from it.
#
# Every mode was entered from a DIFFERENT mode (0->1->2->3->0), so no digit
# rests on elimination.
#
# IMPACT — this one was broken in BOTH layers, unlike the PRI mode-3 gap
# (#341) where only the frontend lagged:
#   - backend set_close_call validated (0..=2) and returned
#     close_call_mode_invalid for 3 — the API could not write the mode the
#     radio was reporting
#   - CLOSE_CALL_MODE_TO_WIRE had no entry for 3, and the read site used
#     `|| 'off'`, so a radio in CC Only displayed as "Off" and the next save
#     would have written CLC,0 — the same silent-clobber shape as #340
# Both fixed alongside this capture.
#
# NOTE on the probe output above: the transition-check summary line printed
# "all three digits" while checking four (a hardcoded count). Fixed in the
# same change; the readings themselves were unaffected.
#
# Band mask 01001 and lockout=1 were untouched; this probe wrote nothing.
